# Практикум: клиенты Kafka, commit и повторная доставка {#lab-the-production-checklist-for-aiokafka}

Запускаемые примеры из [статьи](../../posts/2026-09-13-kafka-in-python-services.md).
Нужен работающий Docker. Выполните команду из
`docs/blog/lab/2026-09-07-aiokafka-checklist` в клоне репозитория:

```bash
uv run --no-project --python 3.13 --with-requirements requirements.txt checklist_lab.py
```

В `requirements.txt` закреплены aiokafka-foundation-kit 0.1.3, aiokafka 0.14.0
и testcontainers 4.15.0. Скрипт создаёт и удаляет собственный контейнер
`confluentinc/cp-kafka:7.6.0` в режиме KRaft. Автоматическое создание топиков
на стороне брокера отключено.

`kafka_flow.py` содержит восемь фрагментов работы с Kafka из статьи: в том числе
обработчик, цикл consumer и управление остановкой. Девятый фрагмент, подключение
servicewright, находится в [практикуме про остановку](../2026-09-07-kafka-consumer-shutdown/README.md).
`lab_support.py` запускает общий стенд и читает сообщения с ограничением времени.

Проверяются следующие результаты:

- опубликованный `ensure_topics_async()` создаёт топик с тремя партициями без подмены функций;
- словари приходят как JSON, ключи остаются байтами, сообщения с одним ключом попадают в одну партицию;
- после чтения пяти записей lag текущей позиции равен нулю, а подтверждённой — пяти;
- ошибка обработчика после двух изменений оставляет пачку неподтверждённой, все пять записей приходят снова;
- учебная витрина пропускает повторы и старые версии статуса;
- после обработки offset 0–4 и ручного commit 5 следующий экземпляр начинает с 5;
- автоподтверждение может сохранить 5 после получения пяти записей и обработки только двух;
- проверка подключения библиотеки возвращает true для работающего брокера.

Витрина в памяти нужна, чтобы наблюдать результат; постоянное хранилище приложения
она не заменяет. Для проверки повтора создаются новые consumer той же группы.
Сценарий автоподтверждения ждёт настоящий периодический commit при открытом клиенте;
обычное закрытие не выдаётся за падение процесса. Проверка подключения не проверяет
права на топик или работу обработчика.

Отдельную проверку публичного API создания топиков можно запустить так:

```bash
uv run --no-project --python 3.13 --with-requirements requirements.txt topic_probe.py
```

Каждая строка `PASS` появляется после успешных проверок. Стенд с одним брокером
не проверяет надёжность репликации или перераспределение партиций во время работы.
