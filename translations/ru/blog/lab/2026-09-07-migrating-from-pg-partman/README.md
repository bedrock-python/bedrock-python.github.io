# Практикум: переход с pg_partman на pg-partsmith {#lab-adopting-a-pg_partman-managed-table}

Во временном контейнере PostgreSQL 17 расширение **pg_partman 5.5.0** создаёт и обслуживает месячные партиции `events`. Затем передаём обслуживание **pg-partsmith 1.5.1**, сверяя объекты таблиц и данные. Сценарий разобран в [статье](../../posts/2026-09-13-postgresql-partition-maintenance.md#migration).

Dockerfile устанавливает pg_partman из исходников с фиксированным тегом `v5.5.0`, без фонового воркера. Все вызовы обслуживания выполняет сам практикум, поэтому старое задание не может вмешаться в переход. Зависимости Python закреплены через файл соседнего практикума хранения партиций. При копировании примера сохраните оба каталога.

Исходники находятся в `docs/blog/lab/2026-09-07-migrating-from-pg-partman`. Из этого каталога, с запущенным Docker и установленным `uv`, выполните:

```bash
docker build -t pg-partman-lab:17 .
uv run --no-project --python 3.13 --with-requirements requirements.txt python partman_lab.py
```

Для сборки образа нужен доступ к репозиториям Debian/PostgreSQL и GitHub. Скрипт проверяет:

- `partman.create_partition` работает с закреплённой версией расширения. Границы месяцев отсчитываются от времени PostgreSQL, которым пользуется и pg_partman.
- `automatic_maintenance='off'` отключает общее обслуживание, но явный `run_maintenance('public.events')` всё ещё может создать нужную партицию. Проверка выполняется до перехода.
- Изучение схемы и построение плана не меняют таблицы. Имена `events_p...` распознаются по границам; отсоединённые pg_partman таблицы без метки не попадают под удаление.
- Срок `'3 months'` отличается от `KeepNewest(count=3)`. Новое правило выбирается явно, это не точное преобразование настройки. `DropNever()` сохраняет отсоединённые данные.
- Запись таблицы в `part_config` удаляется до применения плана pg-partsmith. OID существующих таблиц и все строки сохраняются; отсоединяется только намеченная старая партиция.
- Увеличение горизонта создаёт ровно один новый диапазон. Следующий план пуст, DEFAULT тоже остаётся пустым.

`adoption_flow.py` содержит функции настройки и снятия регистрации из статьи; `partman_lab.py` выполняет проверки. Общие средства запуска БД импортируются из соседнего каталога `2026-09-07-partition-retention`.

При переходе реального сервиса сохраните полные настройки и список таблиц, остановите автоматические и явно адресованные задания, дождитесь активных запусков и только затем снимайте регистрацию. Часовой пояс, интервал, шаблоны, DEFAULT, публикации и правила хранения сопоставляйте отдельно. Этот пример ограничен простой месячной таблицей и не является универсальным конвертером настроек.

Успешный результат — четыре строки `PASS` и код завершения 0. Контейнер удаляется при выходе; собранный локально Docker-образ остаётся для повторных запусков.
